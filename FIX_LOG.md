### F-17 — Blocking reel rendering (HIGH)

- **Root cause:** `POST /api/reels/generate` ran plan validation, credit deduction, and all synchronous composer/FFmpeg work on the request path. `GET /api/reels/{id}` only had completed records, so clients could not observe an in-flight or failed render. FFmpeg and FFprobe had fixed subprocess timeouts, but timeout handling did not explicitly terminate and reap the full process tree.
- **Implementation:** Generation now returns HTTP 202 with a reel ID after bounded admission and submits rendering to a dedicated two-worker executor. The in-memory job store reports queued, processing, completed, and failed states with queued/preparing/rendering/finalizing stages and a terminal error. Frontend callers poll the status endpoint and receive the original completed result shape inside `result`; they show backend stages and preserve the saved reel/download flow. Each request may include a UUID request ID so retries reuse one job without charging or rendering again. Worker failures remove partial final output and preserve refund behavior, including invalid plan music discovered during rendering.
- **Subprocess management:** FFmpeg and FFprobe timeouts are configurable with `AUTOREEL_FFMPEG_TIMEOUT_SECONDS` (default 1800 seconds) and `AUTOREEL_FFPROBE_TIMEOUT_SECONDS` (default 120 seconds). A whole-render deadline is configurable with `AUTOREEL_REEL_TIMEOUT_SECONDS` (default 7200 seconds) and caps each media subprocess for the remaining job time. Media tools run in their own process group; timeout cleanup terminates the process tree (Windows `taskkill /T /F`, POSIX process-group TERM/KILL), waits for the process, and lets renderer temporary directories clean up. Existing output cleanup removes a partial final MP4 on job failure. Stage reporting is coarse at the renderer boundary; individual clip/concat substeps do not expose separate progress events.
- **Compatibility and F-18:** All three frontend generation callers now use the receipt/status contract and still consume the completed download URL/result, including template, selected clip IDs, transition compensation, duration, credit refresh, and saved playback. F-18 remains: reel job metadata and idempotency keys are process-local and are lost on backend restart. No database migration was included. The current API has no user-facing render-cancel operation; a subprocess timeout is cleaned up, while a client disconnect does not cancel a render.
